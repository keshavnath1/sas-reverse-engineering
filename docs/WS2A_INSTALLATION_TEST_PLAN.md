## What the independent reviewer must freeze

1. **Authority and custody.** Record the separately authorized tuple, case IDs, operator, independently authenticated release custodian, expectation author/reviewer, host observer, protected evidence destination, retention owner and expiry. Keep the trusted approval channel, reference bytes and expected results outside the delivered kit, candidate venv and operator's writable area. Bind an exact release revision and its current authorization, including expiry, withdrawal and supersession. A correct hash with no current authority blocks use. Challenge-only artifacts have distinct identities and isolated destinations. They cannot be selected for ordinary use.
2. **Release inputs.** Before candidate execution, freeze the approved manifest identity, lock bytes, exact interpreter/bootstrap and shell/tool provenance, base image/loader/stdlib/startup files, application wheel, nine locked distribution selections, filenames, native/ABI tags, sizes and SHA-256 values. Retain independent reference bytes or protected references to them. Freeze the compatible platform-tag set, exact patch/build, shell and native path spellings, install location, permitted temporary writes and allowed network/process policy. The `py3-none-any` application wheel alone supplies no native dependency.
3. **Installed expectations.** Map each expected venv member to a reviewed input artifact or an explicit, tested generation rule. Include directories, links and allowed targets, interpreter and cfg, site-packages, distribution metadata, installed scripts, bundled resources and any installer-created files. Freeze the exact per-host inputs to path-dependent rules and the independent reference output or bounded derivation for each. Compare every actual member name, type and content/link digest to that expectation. Compare original bytes wherever independently retained, before the custodian authorizes a path-bound WS-1 record. Extra, missing or unexplained bytes block issuance. The observed candidate tree, its own wheel RECORD file and its own `pip check` cannot provide the expected list. Use the shipped twelve-line record format and its closed `.files` companion exactly. Authenticate the resulting final launcher bytes independently before passing them to Bash. The [WS-1 trust bootstrap](WS1_DESIGN.md#trust-bootstrap) sets the framing, limits and location.
4. **Expected behavior.** Freeze the expected argv, command phase, native exit, stdout/stderr comparison, status fields, allowed child processes, path access and write sets for each variant. Freeze a complete help/version/status reference for the named target independently of the candidate. Freeze before/after contents and permissions of the prior installation, active selection, transfer area, inactive destination and outside sentinels. Freeze calibrated challenge inputs and unique witness events. Future setup error diagnostics and exit mappings require a reviewed implementation contract before execution. A failure of unknown origin cannot pass an intended refusal case.
5. **Collection.** Run as a standard user. Record UTC times, case and attempt ID, host OS/build/CPU and filesystem, Bash distribution/build/triple, absolute interpreter invocation and resolved base, Python patch/ABI/platform, verifier/tool identities and release reference. Capture streams separately as original bytes, exit/signal, process tree, file operations and network attempts from before launch to all descendants exiting. Record fixture hashes and native event coverage, including failed operations and attempts on absent paths. Separate observer writes from the candidate process tree. Use synthetic canaries only. Protect raw witness records outside Git, restrict access, and retain redacted references/digests with the reviewer and disposition. An unprotected text log or unchanged mtime alone cannot prove absence of a read.

Each trial starts from the independently registered clean state for its cell. A case requiring an installed candidate or prior selected kit uses a **separately prepared, authorized reference fixture**. A defective candidate from another case cannot become its prerequisite. Rerun the matched positive control with the same observer/identity and vary only the stated input in a fresh fixture. A deliberate missing-input case that cannot reach its own gate because of another missing input remains BLOCKED. In particular, the current Windows closure gap prevents a clean positive install. No test-only override of a native gate is allowed.

## Disposition and handoff

Record each tuple-cell's readiness, attempt count, per-variant command/operation, expected and observed boundary, raw witness references, verifier/reviewer and disposition. Use PASS only after every registered assertion and calibrated control succeeds on the actual target. Record FAIL for a witnessed contradiction, including a forbidden operation even if the process later refuses. Mark unresolved authority, missing witnesses or unreachable variants BLOCKED and preserve any completed observations. Record execution NOT_RUN for cells never started. Keep previous failed/blocked attempts and any later requalification distinct. Report planned, attempted and untouched cells separately from gate or outcome counts. Variants, helper calibrations, duplicate commands, repeat installs and historical test methods do not increase the cell denominator.
