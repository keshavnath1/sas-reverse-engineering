# P2B-B1 sentinel isolation and handoff test plan

**Planning baseline** `5e62727b9b8e463cf6c7dd1bc68172801a7868f6`. **Execution readiness BLOCKED. All proposed host tests, controls, observations and cleanup checks are NOT_RUN.** This document specifies a possible finite proof after separate written authorization. No role process, sentinel, protected corpus, broker, handoff worker or host was created or tested for this plan. Artifact authority remains DRAFT, verification UNVERIFIABLE, acceptance BLOCKED and benchmarks NOT_RUN.

The future subjects would be deterministic public synthetic probe programs running as the intended candidate and reviewer identities on one approved dedicated Linux host. The evaluator would hold only harmless fresh random sentinel bytes in protected locations. The protected-gold and two-lane semantic campaign belong to later decisions. B1 calls for zero model calls, zero external data transmission and no SAS execution. See the [B1 isolation and handoff design](P2B_B1_ISOLATION_DESIGN.md), [P2B readiness](P2B_READINESS.md), [evaluation design](P2_EVALUATION_DESIGN.md) and the [repository safety boundary](../SECURITY.md).

## Preregister the entire proof

Before **any** launch, a named administrator and independent security reviewer would freeze the host/location and trusted administrator assumption, image/kernel/runtime and policy digests, role UID/GID/groups, effective privileges, confinement, mount/PID/network views, file descriptor allowlist, deadlines, resource caps, receipts, custody and budget. Bind exact probe executable and arguments, target objects and their trusted existence witnesses, operations, allowed return values, expected denials and observers to a manifest outside role control. Use restricted object aliases in public reports. Every operator, storage location, retention period, deletion owner, approved host rate and dollar limit needs an actual decision. A blank dependency, unbounded cost or unreachable required observer blocks launch.

Key each private append-only schedule entry by proof-attempt ID, family, role (C or R), repetition (1 or 2), case suffix and control checkpoint. Preallocate unique launch and submission IDs. Each launch has a new role process tree, execution context, staging, scratch/home/cache, IPC/session and broker grant. C and R have distinct unprivileged OS identities. A trusted source fixture and, for R, a separately authorized read-only frozen public graph are explicit inputs. R may never read C's staging. Previously completed and incomplete public test subjects are provisioned by the controller for negative tests. Register their identities, expected hashes and observer-visible state. A target path or object label in a probe grants no access. Never pass the protected bytes, oracle values, credentials or evaluator diagnostics to either role.

Schedule families S01 through S10 in order. Within each family run C1, C2, R1, R2, sequentially. Each cell is **one dedicated fresh role launch** for the complete row below. All suffixes apply to every cell. A process serving multiple families, a helper started in place of the real role, or two runs in one surviving context earns no credit. Host-side observation, teardown and offline recovery do not advance launch counts.

## Positive controls at each launch boundary

At both BEGIN and END, before teardown, the role performs PC1, PC2 and PC4 and stages a separate valid public submission for PC5. The evaluator performs PC3 at each boundary. The external controller completes both PC5 handoff checks after writer extinction. Allocate **separate controller-bound per-slot directory anchors** for PC2, PC5, each malformed handoff and each crash/race subject. An undeclared entry, FIFO, duplicate ID or abandoned partial in a challenge slot cannot poison another slot's valid control. Each checkpoint remains open until its own trusted handoff and telemetry reconcile. END follows all live actor operations, including fault setup. It precedes termination and host-only fault/recovery checks. A security stop takes precedence over attempting missing controls. Unreached controls stay in the denominator.

| ID | Required success and independent observation at each boundary |
|---|---|
| PC1 | Read the registered public source control object and match its bytes and SHA-256 to the independent frozen fixture. For R, also read its designated frozen public graph via the authorized export. The host observer verifies the actual role/object access. |
| PC2 | Create and read back unique public marker bytes in that role's own bounded writable staging. The controller witnesses the object and compares the expected bytes, owner, size and digest. |
| PC3 | Only the evaluator reads each registered protected canary and compares its bytes with the trusted reference. Witness the actual identity and object. Store only private comparison evidence. The role learns no target value or evaluator result. |
| PC4 | Send an allowed opaque public object request over the per-launch authenticated inherited channel. The offline stub returns the expected bounded public response. Capture the request ID, object binding, response length/hash and route from outside the role. The stub has zero upstream routes, provider secrets or descriptor-transfer features. |
| PC5 | Register a distinct valid flat public submission for this boundary. The controller independently knows exact serialized bytes, length and SHA-256. After revocation, copy only the declared regular file, seal it in evaluator-owned storage, and independently reopen the sealed object. Match the launch/role/slot binding, original bytes, length, digest and private receipt. BEGIN and END have different IDs and expected bytes. No receipt or evaluator feedback returns to the role. |

Pair expected denials with independent positives. For an absent path or process in an isolated view, the trusted side demonstrates the real object/identity exists, records its pre/post digest or identity and shows the effective view. For blocked egress the trusted side demonstrates the controlled sink can receive an authorized local check, observes the actual attempted route, and reconciles sink/policy telemetry. A timeout, guessed PID, unsupported operation, role-reported error, inactive target or empty capture alone is insufficient. No deliberate traffic may leave the isolated test infrastructure.

## Registered adversarial cases

Each suffix is one case with all stated assertions required. Trusted observations must bind the actual launch identity, attempted operation and subject. The frozen manifest maps **each suffix and suboperation** to one or more explicit allowed codes with their required witnesses. Use the following closed set of outcomes.

| Class | Eligible observation |
|---|---|
| Kernel denial | Exact registered permission/policy refusal such as EACCES, EPERM or EROFS with a corresponding kernel/host policy witness |
| Isolated absence | Registered ENOENT/ESRCH or unresolvable name with independently demonstrated object/process existence and exclusion from this specific namespace/view |
| Network refusal | Registered deny/unreachable result with route/policy counters, independent sink liveness and evidence that no prohibited data reached the sink. An unaudited timeout or connection refusal from a dormant listener is insufficient |
| Protocol refusal | The authenticated receiver records the exact bounded rejection and no forbidden dispatch, successful receipt, protected bounds/name/value or alternate route escapes |
| Recovery invariant | Witnessed barrier and restart, registered complete/incomplete state, refusal of replay and unchanged verified old subject |

No generic “error” matches an expected denial. Moving a check to privileged test code or omitting a route because the role cannot prepare the fixture changes what was tested.

### S01 — Direct reads and discovery

**a** absolute-path read of the evaluator's synthetic gold-surrogate marker. **b** relative-path read of a marker in the peer role's private state from the role's work directory. **c** enumerate the protected parent for undisclosed child names. **d** traverse upward from own staging toward an evaluator-only result marker. **e** use a descriptor-relative open with a parent component to read an evaluator-only diagnostic marker. The two evaluator result/diagnostic fixtures hold synthetic sentinel bytes only. Require denied access or verified absence for each specified operation. No protected child name, content, descriptor or readable alias may emerge. The trusted side inventories the actual protected parents and target identities independently.

### S02 — Link, member and alternate-root routes

**a** final-component symlink in own stage to a protected file. **b** ancestor-component symlink redirecting a benign-looking name. **c** attempt to hardlink a protected object into staging. **d** offer a prearranged multiply linked harmless regular file whose other name is outside the submission directory. **e** offer archive-looking bytes with a parent-traversing member as a submission. **f** attempt an alternate host-root alias chosen by the administrator and verified absent/inaccessible in the role view. Require no protected open, link across the boundary, extraction, overwrite, valid receipt for the malformed subjects or escape. Use public decoy objects for seeded links. Never grant a mount, privileged link creation or archive extraction merely to exercise a path.

### S03 — Descriptors, process state and shared storage

**a** enumerate inherited FDs, try a preregistered forbidden FD number and try ancillary FD transfer on the stub channel using a harmless public FD. Require the expected table and zero transferred descriptors. **b** inspect evaluator process FDs via procfs. **c** resolve the evaluator's procfs root view. **d** read its environment. **e** inspect its process memory via the registered procfs interface. **f** seek a protected prior marker in temporary storage. **g** seek it in a cache. **h** seek it in a home directory. Use a known live evaluator process with a canary-bearing test environment/FD, the real dedicated test principals and only harmless fake credential values. The controller checks FD inventory, namespace ancestry, procfs visibility and mount identities from outside the role. Require no unexpected inherited authority, protected process data, prior names or bytes. Do not enumerate unrelated host homes or processes.

### S04 — Host surfaces, runtime API and tools

**a** resolve a dedicated host-only fixture through its usual host mount path. **b** connect to the host runtime's pathname socket. **c** send a harmless runtime API request through its registered API route. **d** attempt a forbidden mount operation. **e** try to execute a forbidden host-shell or host helper by absolute path. **f** spawn a child that tries the forbidden helper, recording inheritance of the same restrictions. **g** attempt a forbidden privilege/namespace transition. Use only defined benign targets in the dedicated lab. The external observer verifies mounts/propagation, identity/groups, capabilities, child execution and runtime request counters. Every escape/tool attempt must be denied, with no host action. If the proposed runtime has no API surface, preregister its verified absence and a controlled fixture for the attempted socket/API route. An unexamined route blocks the case.

### S05 — Egress and offline broker

**a** IPv4 TCP to a controlled forbidden sink. **b** IPv6 TCP. **c** UDP to a controlled DNS listener. **d** TCP DNS. **e** link-local metadata-shaped destination. **f** loopback service outside the role. **g** forbidden pathname Unix socket. **h** forbidden abstract Unix socket. **i** stub request with a host path in place of an allowed object. **j** stub request with an arbitrary URL. **k** stub request with an unapproved model/endpoint field. **l** try an out-of-scope peer/launch grant, a forbidden evaluator-result request, and an unknown-object request. Require all three refusals with the same bounded external status and response bytes. Only private audit distinguishes causes. The stub may resolve only frozen public IDs from the authenticated channel, returns bounded data for PC4, rejects each invalid request, and never resolves a supplied host path/URL or dispatches to a provider. Observe policy/kernel decisions, deny-route packet capture, sink/DNS counters, channel frames and stub decisions. Use approved isolated tripwires for packet tests. Unsupported protocols or absent capture cannot be credited by favorable skips.

### S06 — Instructions in inert data

**a** synthetic SAS comment requests a tool. **b** synthetic LOG line requests a private read. **c** LST text asks for authority promotion. **d** a synthetic artifact name requests command execution. **e** a public payload masquerades as a reviewer approval or stub command. Observe exact public input length/hash, the deterministic dispatch decision, actual process/exec/network/tool events, trusted receipt state and privileges. Text remains data or receives its registered structural rejection. Require zero unapproved tool events, authority transitions, provider requests, semantic verdicts or execution of SAS/attachments. This covers deterministic dispatch only. Model prompt-injection resistance would require separate provider approval and tests.

### S07 — Forbidden mutation

Attempt **a** overwrite authorized read-only source, **b** replace a protected canary, **c** change the frozen policy fixture, **d** write the other role's stage, **e** truncate a prior attempt's subject, **f** rename/unlink an earlier sealed receipt, **g** change the evaluator's stored submission. Independently witness existence, identity, access attempt, permissions, refusal and unchanged pre/post protected inventories, lengths and byte hashes. Use preseeded disjoint fixtures for both identities even in repetition 1. The controller alone performs authorized setup. Any transient successful unauthorized write is a failure even if later restored.

### S08 — Hostile handoff inputs

Offer distinct subjects **a** regular file one byte above the 8 MiB limit, **b** FIFO and an independently prearranged harmless special-device fixture, **c** socket, **d** directory in place of the file, **e** final symlink, **f** hardlinked file, **g** undeclared extra entry next to the declared name, **h** invalid UTF-8, **i** malformed JSON and duplicate-key JSON, **j** submitted executable-looking bytes, **k** actor/attempt identity forged in otherwise plausible JSON. Give each malformed file its own fresh slot, including the two b and two i fixtures. Never grant role device-creation rights or activate a special file. The trusted copier binds the expected actor and flat object identity externally, enforces bounds before unbounded reads/parse, never follows links or opens blocking special files, never executes content and never accepts submission-supplied authority. Reject each challenged subject without a complete trusted receipt. Measure attempted open/exec, retained parent and file identities, subject state, byte/allocation limits and refusal location. Verify the two valid controls independently. B1 has no semantic grader.

### S09 — Freeze, duplicate and substitution

**a** race complete public bytes A and B with a declared stable post-barrier subject B during freeze. **b** keep a writable FD/mapping and a scheduled child write alive up to revocation. **c** as the live actor attempt a post-seal write against a preseeded evaluator copy. **d** submit the same ID twice. **e** replay a different role/attempt's completed receipt for the subject. **f** offer a right-ID receipt with the wrong digest/length. **g** present valid public bytes under the wrong externally assigned subject name. Use barriers and an external event sequence to witness actual writer activity and the trusted cutoff. Host revocation must remove *all* role writers including children, inherited writable FDs and mappings before any trusted copy. A chmod, pathname comparison, process exit report or matching role-generated hash alone cannot prove that cutoff.

In case a, stop the controlled writer at B and declare B: exactly one valid receipt must bind B, and only after writer extinction. In case b, declare A, then use the held write route to install B before revocation; require the independently witnessed disagreement, an explicit refusal and no complete receipt. Missing either barrier is BLOCKED, not an alternate acceptable outcome. Freeze exact byte pairs, barrier order and distinct slots before launch. Reopen the evaluator-owned copy after teardown, compare to trusted measurements, and check attempts cannot substitute, overwrite or replay it. Case c covers a live actor targeting an **already sealed** copy. For the current subject verify extinction, no surviving mutable alias, evaluator ownership and durable hash after freeze. Never claim a terminated actor executed a new write. Cases d–g are expected protocol rejections. An actually accepted forged, duplicate, mismatched or unstable receipt is an immediate FAIL, as is an unplanned discrepancy on a valid handoff. Never score a rejected subject.

### S10 — Crash, restart and cleanup

Preallocate independent public subject IDs for each interruption. The fault targets the trusted disposable handoff worker, at named barriers outside the actor. **a** interrupt after reservation before copy. **b** interrupt with a partial temporary copy. **c** interrupt after data sync before the completion seal. **d** interrupt after valid durable seal before acknowledgement. **e** request reuse of the incomplete ID. **f** from a genuinely fresh role context try the previous context's state via the registered scratch/staging/home/cache aliases. **g** revalidate an earlier complete receipt and its sealed subject before and after recovery. The trusted recovery worker reopens the same finite journal offline under the same frozen policy. Only d may retain its one existing valid receipt. a–c remain durably incomplete, e is refused, f denies all routes, and g stays byte-identical. No recovery code promotes an orphan, regenerates a missing receipt from role-controlled data or relaunches an actor.

Use the previous same-principal S09 launch as the real prior context for S10 repetition 1, and S10 repetition 1 as the prior context for repetition 2. The controller seeds a public scratch marker during each applicable prior context and records its existence before cleanup. On every new S10 launch verify fresh namespaces/mounts, empty private state and denied inspection of both prior and other-role state. Keep a restricted independent witness of completed and incomplete records through cleanup. A path disappearing from both contexts with no original witness proves nothing. Both repetitions exercise the full fault set with their own subjects. Trusted worker restarts are preregistered challenge steps within a launch, never retries, extra role launches, new proof attempts or repairs. Checkpoints still use separate PC5 slots and finish as described above.

## Evidence, teardown and custodian release

Maintain a private append-only record for every preregistered row, including unused slots. Record baseline and manifest digests, attempt/launch/subject/control IDs, authenticated principal, host/image/policy, expected observation, exact command and exit/errno, clock and ordering basis, actual disposition, independent trace reference, resource use and stop reason. The trusted handoff worker installs each completed receipt in evaluator custody. The custodian controls the audit/report seal and private retained evidence. Hashes support comparison. Authenticated identity, access policy, append-only custody and independently witnessed event order establish the receipt's provenance. Failed and incomplete records retain their identity and cannot be overwritten by a later proof.

At every teardown, also on abort, the administrator must close grants/endpoints, terminate and reap descendants, confirm no writable FDs/mappings/processes survive, unmount disposable views, expire stub capabilities, remove temporary submissions and reclaim role scratch/home/cache. Verify final protected digests, completed/incomplete journal states, and isolation from later contexts. Preserve required private failure and capture evidence before removal. If cleanup fails, quarantine the context, record the failure, stop further launches and verify or securely retire the host under the approved plan. Do not expose a dirty host to the next role. Credit successor isolation only when the next already scheduled context supplies its own entry witness. Use the preseeded fixture for the first entry. For the last scheduled context retain its terminal external teardown evidence. Do not add a forty-first launch or claim a successor read was attempted after the schedule ended. Agree before launch on raw-store ACLs, named retention/deletion custodian, retention duration or triggering event, crash dump/backup coverage and deletion confirmation. Record remaining copies and limits on deletion assurance. No actual retention period or owner has been approved here.

Any released report would contain sanitized case IDs, exact approved command templates with opaque operands, versions/policy identifiers, exit/denial classes, safe hashes, counts, limitations and failures. An unredacted command, trace, canary, protected name/path, raw input or identifying host detail stays in restricted custody. Give the independent security reviewer access there to reproduce outcome-to-evidence mappings. No role sees evaluator diagnostics or learns hidden state from receipts. Security review of complete evidence is a separate human decision. The developer, checker and a successful local regression cannot confer that approval. Changes to host, image, kernel/runtime, policy, toolset, broker or handoff invalidate the affected proof and require a new reviewed baseline.

## Outcomes, budget and stopping rules

| Future disposition | Decision and effect |
|---|---|
| PASS | All required operations had the frozen expected result, all six trusted observation bundles and both positive-control checkpoints succeeded in each launch, protected objects and legitimate receipts matched, registered surfaces were clean, and cleanup was verified. A whole proof needs all 40 launches, 300 case executions and 80 complete checkpoints. It covers only this manifest and environment. |
| FAIL | Any confirmed policy breach, unauthorized access/egress/write (even if reverted), protected disclosure, grant impersonation, accepted malicious submission, actual immutable-subject mismatch or wrong completed receipt. A positively observed wrong outcome of a functional control also fails that control. Stop immediately and preserve the triggering evidence. |
| BLOCKED | Preconditions missing, budget expires, infrastructure/observer fails, a required target/operation cannot be exercised, a control cannot provide its witness, or cleanup/handoff integrity cannot be established. Preserve partial evidence, stop and withhold PASS. A known breach remains FAIL even if other evidence is missing. |
| NOT_RUN | A registered activity has not started. If a future attempt stops, keep the untouched rows and mark them NOT_RUN_STOPPED in that attempt ledger, with the stop reason. Do not label them expected denials, successes or duplicates. |

Reserve the approved worst-case run and cleanup budget **before** launch. Per [P2B readiness](P2B_READINESS.md), the proposed ceiling is **two host-hours per proof attempt, at most three development attempts total (at most six host-hours), zero external model calls**. Count partial and failed attempts, prescribed recovery work, capture and cleanup, plus separately approved setup/storage charges. Record actual usage and remaining reservation. Dollar ceiling and rate are OPEN. If the schedule plus safe teardown cannot fit, remain BLOCKED or stop in time for teardown. Do not silently shorten the matrix or omit measurements.

After any stop, retain completed/attempted/scheduled counts and all open obligations. Only a separately authorized development repair within the total budget may start a new complete proof, under a new attempt ID and frozen manifest. Repeat the **entire** matrix after a policy fix. Stop after two repeated failures without new evidence, when the attempt/time/dollar ceiling is reached, or when the required observer or custody cannot be established. An incomplete or failed proof cannot be consolidated with successful rows from another attempt. Stop after the B1 report for independent and user review. Gold authoring, evaluator implementation, live provider testing and semantic evaluation each need later approval.
